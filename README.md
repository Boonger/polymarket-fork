# cryptomarket.terminal

Мини-клон Polymarket для **BTC Up/Down**: окна 5 минут, 15 минут и
4 часа. Real-time график на Chainlink TWAP (том же источнике, на
котором резолвится сам рынок), стакан бинарного контракта (UP/DOWN),
лента сделок и системный лог — тёплый стеклянный (glassmorphism) UI.

React + Vite, без бэкенда. Деплоится статикой на GitHub Pages.

## Что внутри

Всё — реальные данные, без бэкенда и без API-ключей:

- **График** — не Binance, а тот же Chainlink TWAP, на котором
  фактически резолвится рынок Polymarket: внутренний роут
  `polymarket.com/api/crypto/price-history`. Опрашивается раз в 30с
  (5m/15m) или раз в 60с (4h) — редкий поллинг вместо стрима сделан
  специально, см. раздел "Про память" ниже.
- **Рынок** — резолвится динамически: для 5m/15m строится
  детерминированный slug (`btc-updown-5m-{unix_ts}`), для 4h —
  ищется среди активных ивентов Gamma API (см. раздел ниже). По
  найденному рынку вытягиваются `token_id` обоих исходов (Up/Down).
  При смене окна рынок резолвится заново автоматически.
- **Стакан (Up/Down)** и **лента сделок** — реальный публичный канал
  `market` CLOB WebSocket Polymarket, подписка по `assets_ids` двух
  токенов исхода. Без авторизации — это read-only рыночные данные.
- **Страйк / обратный отсчёт** — первое значение TWAP в открывшемся
  окне рынка, и таймер до его закрытия.

## Про TWAP price-history и предположение по 4H

Формат запроса — из твоего примера:

```
https://polymarket.com/api/crypto/price-history
  ?symbol=BTC
  &eventStartTime=<ISO окна рынка>
  &variant=fiveminute|fifteenminute|fourhour
  &endDate=<ISO текущего момента>
  &twapEnabled=true
  &twapLookbackSeconds=30|60
```

- `fiveminute` / `fifteenminute` — подтверждены твоим примером.
- `fourhour` — **предположение по аналогии**, публичной документации
  на этот (внутренний) роут нет. Если 4H не отдаёт данные — открой
  polymarket.com на карте BTC 4H, вкладка Network, найди реальный
  `variant` и поправь `INTERVALS['4h'].variant` в
  `src/utils/polymarketSlug.js`.
- `twapLookbackSeconds`: 30 для 5m/15m, 60 для 4h — как ты и просил,
  задано в том же файле.
- Опрос: раз в 30с для 5m/15m, раз в 60с для 4h — тоже в `INTERVALS`.

Это первый запрос к домену `polymarket.com` (не `gamma-api.` /
`clob.`) в проекте — это внутренний Next.js API-роут их же фронтенда,
не публично документированный CLOB/Gamma API. CORS для него не
проверялся вживую (нет доступа к браузеру из среды, где собирался
проект) — но раз это тот же эндпоинт, которым пользуется сам
polymarket.com при рендере графика в браузере пользователя, отсутствие
CORS было бы для них самих же проблемой. Если всё же наткнёшься на
CORS-блок — единственный обходной путь на чистой статике GitHub
Pages — лёгкий прокси (Cloudflare Worker/Vercel function), сам
GitHub Pages бэкенд не хостит.

## Как резолвится рынок

Логика в `src/utils/polymarketSlug.js`:

- **5m / 15m** — slug стабилен и не зависит от таймзоны:
  `btc-updown-{interval}-{unix_ts}`, где `ts = floor(now/N)*N` в UTC.
  Один запрос `GET gamma-api.polymarket.com/events?slug=...`.
- **4h** — как и было верно для 1h/1d в предыдущей версии, слаг у
  Polymarket завязан на Eastern Time (плавает из-за DST) и менял
  формат — гадать его вручную ненадёжно. Вместо этого запрашивается
  список активных ивентов (`/events?active=true&closed=false`) и
  среди них ищется тот, чьё название/slug указывает на 4-часовое BTC
  окно, а `[startDate, endDate]` содержит текущий момент.
- Из найденного ивента берётся `clobTokenIds` (JSON-строка с двумя
  token_id — Up и Down) и `outcomes`, чтобы сопоставить исходы.

## Как читается стакан/лента

`src/hooks/usePolymarketBook.js` открывает WebSocket на
`wss://ws-subscriptions-clob.polymarket.com/ws/market`, подписывается
на оба `token_id`, обрабатывает `book` / `price_change` /
`last_trade_price`. Раз в 10с шлёт keep-alive `"PING"`. Watchdog: если
20с нет вообще никакой активности — форс-реконнект.

## Про память (было ~4ГБ за 15 минут)

Причина была в предыдущей версии на Binance: сырой `@trade` стрим
шлёт десятки сообщений в секунду, и **каждое** тут же вызывало
`setState` → полный ре-рендер дерева, включая Recharts (перестройка
SVG). За 15 минут — многие тысячи полных перерисовок графика, отсюда
и рост памяти (GC не успевал, плюс известные проблемы Recharts с
ResizeObserver при частых ре-рендерах).

Исправлено в двух местах:

1. **График больше не привязан к высокочастотному стриму.** Источник —
   поллинг TWAP price-history раз в 30–60с (см. выше). Ре-рендер
   графика теперь бывает не чаще раза в 30 секунд, а не десятки раз в
   секунду.
2. **Стакан/лента троттлятся.** `usePolymarketBook` больше не дёргает
   ре-рендер на каждое сообщение WebSocket — входящие апдейты копятся
   в `Map`/буфер, а единый `setInterval` раз в 200мс решает, применять
   ли их к состоянию React. Ре-рендер этой части UI ограничен ~5
   раз/сек независимо от того, сколько сообщений реально пришло от
   CLOB (в волатильные моменты это могут быть десятки в секунду).

Если через 15+ минут открытой вкладки память всё ещё растёт заметно —
это, скорее всего, либо накопление вкладок DevTools/расширений
браузера, либо стоит проверить через Chrome Task Manager (Shift+Esc),
что именно растёт: JS heap самой вкладки или GPU-память (WebSocket
сам по себе, без данных выше, накоплений не создаёт).

## Структура проекта

```
src/
  components/
    Header.jsx           — брендинг, интервал (5m/15m/4h), статус
    Tape.jsx              — бегущая лента реальных сделок (стекло)
    PriceChart.jsx          — график на Chainlink TWAP + страйк + таймер
    OrderBook.jsx            — реальный стакан Up/Down с барами глубины
    TransactionLog.jsx        — консоль с логом реальных транзакций
  hooks/
    usePolymarketMarket.js     — резолв текущего рынка по slug/поиску
    usePolymarketBook.js        — WS к CLOB (стакан + сделки), троттлинг, watchdog
    usePriceHistory.js           — поллинг Chainlink TWAP price-history
  utils/
    polymarketSlug.js             — slug/поиск рынка, INTERVALS-конфиг, парсинг token_id
    format.js                      — форматирование чисел, центов, времени
  index.css                        — дизайн-система (тёплое стекло, токены, layout)
```

## Дизайн

Тёплый glassmorphism: матовые стеклянные панели (`backdrop-filter:
blur`) поверх мягкого градиентного "неба" из размытых кремовых,
персиковых и шалфейных пятен. Display-гарнитура Fraunces — для
крупной цены и брендинга (характер, а не безликий sans), Inter — для
интерфейсных подписей, IBM Plex Mono — только для данных (цены,
объёмы, время), чтобы цифры были табличными и предсказуемыми. Один
акцент — тёплое золото; рост/падение — приглушённые зелёный/кирпичный,
тоже в стеклянных "пилюлях", а не плашках.

## Известные ограничения

- Только BTC. Список активов не расширялся по твоей просьбе.
- `variant=fourhour` для 4H — предположение, см. раздел выше.
- Реконнект CLOB WebSocket при разрыве/тишине — до ~20с; в этот момент
  стакан временно "замирает" на последнем известном состоянии.
- Это **read-only** просмотр. Размещение ордеров требует EIP-712
  подписи кошелька и не может безопасно выполняться из публичного
  фронтенда на GitHub Pages — для этого нужен отдельный бэкенд/бот с
  приватным ключом.
